# PostgreSQL Exchange store

`PostgresExchangeStore` persists gold wallets, gap-free wallet entries, operation receipts, listings, and pending/committed/compensated trade or listing settlements. The installed schema marker is version 1; every call checks it. A transaction advisory lock serializes decisions across workers; listing commit advances its current revision atomically. SQL classes 22 and 23 reject without retry; storage failures fail closed. Use the existing pinned Npgsql 10.0.3 package.

The caller authenticates character and inventory ownership and validates listing eligibility with the Exchange domain rules. Item escrow is funded before a listing or trade settlement begins. `BeginTrade` and `BeginPurchase` reserve the exact spend; the coordinator delivers the stored `EscrowDelivery` batch through InventoryLedger with `operationId + "/settle"`, then calls `Reconcile`. After a crash, fence the worker before reconciliation. Recovery reads the durable ledger receipt in one ledger transaction. If absent, it writes a zero-change tombstone at the same operation key; ledger fingerprint checks then reject late delivery. A matching receipt, including container revisions, posts both transfer sides and the fee once. Compensation releases the reservation without a guessed inventory refund. Inventory outages leave settlement pending; ledger rejection is non-retryable. Listing and transaction fees are supplied from one bounded `ExchangeSettings` snapshot by the coordinator; there are no new tunables. An active listing remains reserved while settlement is pending.

This is a storage and coordination boundary, not an authenticated network API. Production worker fencing, escrow funding orchestration, automatic recovery scheduling, and a shared configuration publisher remain integration work. ponytail: the global advisory lock serializes all exchange writes; partitioning it requires durable per-subject worker fencing. Backup and restore support is a later task.
