# Chat contacts service

`Chat.Host` is a loopback gRPC service for directed friend and block contacts. It owns no chat messages or mail yet. Install the chat schema and `Schema.Erasure.sql` with `SchemaMigration.Tool chat` under `chat_owner`, then grant the runtime role `USAGE` on `chat` and DML on its tables only. Start with `CHAT_HOST_PORT`, `CHAT_CONNECTION`, `SF_CHAT_TOKEN`, `SF_CHAT_PRIVACY_TOKEN`, `CHAT_IDENTITY_URL`, `CHAT_IDENTITY_SERVER_ID`, and `SF_IDENTITY_CHAT_VERIFIER_KEY`. Keep both service secrets on trusted hosts.

For add, remove, list, and whisper checks, a trusted caller supplies its service token plus `x-contact-ticket` from IdentityGateway's authenticated `/v1/characters/{characterId}/contacts-ticket`. Chat.Host consumes that short-lived, one-time ticket through `/v1/chat/verify-ticket` and rejects a request whose `character_id` differs from the ticket actor. World-entry tickets have a separate server scope. `IsBlocked` is service-only. `CheckWhisperDelivery` is the server-side policy check: either block direction denies a whisper; friendship is directed and never required for delivery. The chat WebSocket delivery transport remains pending.

`AddContact` and `RemoveContact` require an idempotency key, return whether the original operation changed a row, and reject key reuse with changed input. `ListContacts` returns only outgoing edges. `EraseContacts` requires the separate privacy token, removes incoming and outgoing edges for the supplied subject character IDs, and leaves tombstones so contacts cannot be recreated after erasure. The privacy workflow supplies the subject's character IDs; it does not write the chat database directly.

Focused check: `pwsh tools/Test-ChatContacts.ps1 -EvidenceRoot Artifacts/Persistence/ChatContacts/<fresh-child>` uses the pinned SDK and owned PostgreSQL instance, checks real IdentityGateway tickets, contacts, whisper policy, privacy erasure, DML-only runtime role, and host restart. It stops all processes it starts.
