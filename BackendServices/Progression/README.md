# Progression receipt model

Package-free in-memory model for accepted gathering harvest, craft conversion, and enemy defeat receipts. It uses registry IDs `skill/logging`, `skill/mining`, and `skill/smithing`. Formula version 1 is fixed in code; an injected clock and roll source make outcomes repeatable. Accepted receipt IDs are retained for idempotency. Rejected receipts have no effect. Practice grants character XP even when a skill roll fails or its unspecialized cap blocks a gain.

`ProgressionSettings` is an immutable effective snapshot with typed bounded defaults. It declares base gain rate, maximum chance, attempt weight, fatigue and repetition windows, thresholds, hourly gain reference attempts, and rested accrual ratios (offline minutes per rested minute), cap (rested minutes), XP multiplier and skill gain multiplier. The shared configuration workflow must publish it; this model has no console editor. The snapshot is captured at character-model creation and applies until that instance ends. No runtime config-service connection exists yet.

Run `& Artifacts/Persistence/Toolchains/dotnet-10.0.402/dotnet.exe run --project BackendServices/Progression.Tests --locked-mode` from the repository root.

`CharacterState.Postgres` persists snapshots, effective settings and source receipts through this model. The final accepted practice receipt may set `session_end` and `in_rest_area` atomically with its XP/skill write; `EndSession` closes a session with no accepted final practice receipt. The next `GetCharacterState` accrues rest once and exposes the pool. Accepted kill and noncombat practice receipts receive rested XP and skill gain multipliers and debit one rested minute per active wall-clock minute. This slice has no skill locks/donors, specialization, diversity modifiers, timing/risk anti-macro signals, or separate configuration publisher. Enemy defeat uses base eligible kill XP with tier, level difference, and party scaling; trusted producers must validate combat eligibility before acceptance.
