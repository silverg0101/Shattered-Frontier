# Progression receipt model

Package-free in-memory model for accepted gathering harvest, craft conversion, and enemy defeat receipts. It uses registry IDs `skill/logging`, `skill/mining`, and `skill/smithing`. Formula version 1 is fixed in code; an injected clock and roll source make outcomes repeatable. Accepted receipt IDs are retained for idempotency. Rejected receipts have no effect. Practice grants character XP even when a skill roll fails or its unspecialized cap blocks a gain.

`ProgressionSettings` is an immutable effective snapshot with typed bounded defaults. It declares base gain rate, maximum chance, attempt weight, fatigue and repetition windows, thresholds, hourly gain reference attempts, rested accrual ratios and bonuses, plus kill XP kills-per-level (150, bound 1–1000) and additional party share (0.2, bound 0–1). The shared configuration workflow must publish it; this model has no console editor. The snapshot is captured at character-model creation and applies until that instance ends. No runtime config-service connection exists yet.

Run `& Artifacts/Persistence/Toolchains/dotnet-10.0.402/dotnet.exe run --project BackendServices/Progression.Tests --locked-mode` from the repository root.

`CharacterState.Postgres` persists snapshots, effective settings and source receipts through this model. The final accepted practice receipt may set `session_end` and `in_rest_area` atomically with its XP/skill write; `EndSession` closes a session with no accepted final practice receipt. The next `GetCharacterState` accrues rest once and exposes the pool. Accepted kill and noncombat practice receipts receive rested XP and skill gain multipliers and debit one rested minute per active wall-clock minute. This slice has no skill locks/donors, specialization, diversity modifiers, timing/risk anti-macro signals, or separate configuration publisher. Enemy defeat uses the highest eligible party level, party size and tier in the designed kill XP formula. The trusted zone server selects living same-party members within the configured 60 m radius and sends one receipt per member; the host bounds the submitted reference level and party size. Legacy solo receipts with reference level 0 use the recipient's level. Durable party membership belongs to `group-service`, not Gameplay.Host.
