# Premade group persistence

`Gameplay.Host` maps `sf.group.v1.GroupService` when `GAMEPLAY_GROUP_CONNECTION` is set. The trusted dedicated server keeps the current party rules in its session model, sends accepted create/join/leave/kick/role changes to the host, and restores connected members by character ID after reconnect or world-server restart. Invitations still expire in the Unreal session. This slice covers five-member same-realm premades; Redis live state, LFG, extended parties, and group loot remain later design work.

Apply `BackendServices/Group.Postgres/Schema.sql` through `SchemaMigration.Tool group` under an owner role before host startup. Grant the runtime role `USAGE` on `"group"` and `SELECT,INSERT,UPDATE,DELETE` on its tables only. The runtime store never executes DDL. `"group"` must remain quoted in SQL. `GroupControls` declares a shipped five-member limit with bounds 2–5, effective on host restart; the session invite TTL and XP radius remain in `USFPartySettings`.

Focused check: `pwsh tools/Test-GameplayHosts.ps1 -GroupOnly -EvidenceRoot <fresh Artifacts/Persistence/GameplayHosts child>` with the pinned SDK. It checks wire replay, conflict, membership, roles, DML-only access, and host restart.

Raid loot membership: owner migration `Schema.Raids.sql` links up to five active same-realm parties under one durable `rgp_` ID, with at most 25 current members. Trusted `CreateRaid` and `AddPartyToRaid` RPCs require the current leader of the founding party and identify the current leader of the joining party. `GetPartyForCharacter` returns its party and full raid roster. The Unreal zone server caches that roster on reconnect and party mutations, then applies the existing living, 60 m, and protected-town checks at defeat. Ordinary kills grant each selected character a personal roll; a unique/boss shared-drop snapshot stores the raid ID and allows one claim. Defeat grants create ledger gear instances for gear drops. The `raid-rewards` GroupOnly wire leg checks two parties, personal grants and one boss claim.

Owner decisions needed (defaults used here): how players initiate and consent to a raid link (trusted server RPC with both leaders identified; no player-facing flow); how an externally linked raid updates connected zone servers (reconnect until a raid workflow is wired); how parties leave or disband a raid while other parties remain (only disbanded parties cease contributing to the roster). The open-world loot radius uses the existing 60 m party setting. Instance size classes, bench rules, lockouts and raid loot modes are outside this slice.
