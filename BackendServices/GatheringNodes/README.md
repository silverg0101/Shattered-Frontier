# Gathering node MVP

`GatheringNodeService` creates deterministic active node instances from gathering groups in a validated zone record. This slice supports `oak_tree` wood and `stone_outcrop` mined stone through caller supplied definitions. Silverbrook has no iron vein group, so stone is the available ore category pilot. Unsupported definitions are excluded and no WorldContent file is changed.

The injected `TimeProvider` drives depletion and regrowth. Commands carry operation ID, player ID, node ID and generation; a process local receipt makes retries identical, and a lock serializes the last charge. Generation increments at every regrowth, including each partial charge. Retrying an old operation returns its receipt; a new operation carrying an old generation is rejected. Restart persistence, inventory grants, range and tool checks, network authority, World scarcity, spawn point rotation, and Crafting quality rolls are integration work.

Definitions declare charges (1–20 harvests) and yield (1–100 units per harvest). `NodeSettings` declares respawn delay (30–3600 seconds; shipped 300), jitter (0–25%; shipped 10%), and full or partial regrowth (shipped full). Configuration is captured at service creation. A future shared configuration publisher can supply a validated settings snapshot; operators cannot edit formulas. These settings are realm controlled, require `world.tuning.publish`, and apply to newly created service instances; scheduled timers retain their captured values. `stone_outcrop` remains a mining stand in until authored iron content exists.

Gathering definitions in zone content may declare `growth_profile` for full respawn. Its `grow_fraction` is a fraction of the scheduled respawn interval (default 0.5, bounded strictly between 0 and 1). Two to four named stages have `duration_fraction` units of that growth window: positive durations for all but the final mature stage, whose duration is zero; the durations sum to 1. Each `yield_fraction` is strictly increasing in (0, 1], ending at 1. Stage fractions and durations in the iron vein content are **tuning placeholders** pending owner balance. The zone validator also applies GAT-01's no-early-harvest-advantage rule: `yield_fraction ≤ (respawn_s − grow_s + start_fraction × grow_s) / respawn_s`. Service creation checks the rounded charge counts against the same bound. These values are realm controlled, require `world.tuning.publish` through the shared configuration workflow, and take effect for new service instances after compatible content publication; scheduled timers retain their captured values. The formula and bounds are versioned code.

The server derives stage and stage start from the clock; snapshots expose both. A stage's available charges are `max(1, round(charges × yield_fraction))`, less charges already harvested in that growth cycle. The last charge depletes the node and schedules the next cycle. Definitions without a profile keep their existing full and partial regrowth behavior. Gameplay.Host exposes `GetNode` and idempotent `Harvest` through `proto/sf/gathering/v1/gathering.proto`; the dedicated server projects host snapshots into replicated charges, depletion, stage and recovery time when Gameplay Services is enabled. Host node state and receipts remain process-local across restarts.
