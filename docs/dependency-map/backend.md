# Backend

LAN release closure: `tools/Build-PlayableServiceRelease.ps1` exports both hosts, owner migration tool, content/base schemas and hashes from one clean committed revision; `ops/steam-server/Services.Dockerfile` pins its ASP.NET runtime. `ops/steam-server/playable-release.md` records durable LAN topology, role/secret constraints and apply/rollback. Frozen ff59 is deployed; native loot/SQL/restart acceptance is paused for owner-requested client fixes. Current evidence and the known HUD489/60 discrepancy are at the top of `docs/e1-linux-server-build.md` and the named runtime hand-off.

`SchemaMigration.Tool playable-init|playable-verify` is the owner-only fresh LAN database bootstrap/role checker; it refuses nonempty stores and installs five schemas under NOLOGIN owners. Runtime roles have DML without DDL/version/history changes; only the CHECK-true singleton key allows column UPDATE for existing FOR SHARE admission locks. Inventory gets repair's exact Exchange grants; CharacterState gets SELECT on recovery's pending housing/Exchange rows. `Gameplay.Host runtime-probe` checks ledger read and World rejection with correct/incorrect private bearers without changing durable state. `ops/steam-server/playable-runtime.py` validates/renders/starts only its fixed LAN or unpublished owned service-check project; its private rendered Compose contains credentials and must remain 0600. See the rollout document for commands/operator gate.

Existing-store release switches reuse `start` (verification-only, stable secrets/data), never `prepare`/`init`; guarded maintenance and existing-playable rollback are documented in `ops/steam-server/playable-release.md`. The pending disk/profile preparation is `hand-offs/queue/backend-playable-runtime-update.md`; `tests/test_playable_runtime.py` includes a POSIX lifecycle preservation/refusal check in addition to strict profile tests.

World loot: `InventoryLedger/WorldLoot.cs` stores source metadata, escrow items/copies, shared claimant and idempotent receipts in existing ledger transactions; zone ownership uses the existing indexed container lookup. `Gameplay.Host/WorldLootGrpc.cs` adds Rewards create/list/open/take/drop RPCs; canonical CreatureLootRules remain the roll authority and a defeat route fence excludes direct grants. All recipients are frozen in one transaction and replay saved rolls after content changes. Metadata also carries the opaque authoritative defeat/body ID so recipient projections can share physical-body identity without parsing slot IDs. Optional asset-local mesh bounds persist in the same metadata JSON and additive Rewards messages; absent values preserve legacy admission/source fingerprints. DropLoot also persists optional bounds/full pose before its existing atomic debit. Ground metadata validates Engine5.8 HALF_WORLD_MAX1 local/scaled/transformed-corner geometry; the existing corpse envelope is unchanged. No database schema or topology change. Targeted checks: `InventoryLedger.Tests --world-loot` and `tools/Test-WorldLootDurable.ps1 -EvidenceRoot <fresh ignored child>` (owned PostgreSQL immediate restart/concurrent pickup/body-ID recovery).

Reusable NPC slots: `WorldContent/NpcSpawnCatalog.cs` replaces Silverbrook group/species allowlists with declared NPC groups and canonical schema-3 profile `respawn_tier` (schemas 1/2 are rejected after required preset/bounds semantics were introduced); `WorldSlotsGrpcService` and the finite bridge retain wire fields. Gameplay.Host uses an approved restart-bound `GAMEPLAY_ZONE_ID` (Silverbrook default) for protected/gathering/NPC content. Run WorldContent.Tests with `--npc-reuse` and `--combat`, WorldContent.Tool zone validation, and the focused archer services netcheck.

Character creation archetype: `Progression/CombatAttributes.cs` declares the Part 6 ids and allocations. `ProgressionGrpcService.CreateCharacter` validates `archetype_id`, derives the base on the server, and stores it through `EnsureCombatIdentity`; repeat gateway logins accept the same appearance and choice. `IdentityGateway` validates and persists the id (`Schema.Archetype.sql` upgrades old rows to Fighter), and its authenticated world verifier supplies the stored id and appearance for the Unreal session's create-before-restore call. Focused checks: `IdentityGateway.Tests`, `Test-GameplayHosts.ps1 -AppearanceOnly`, and `Test-CharacterStateDurable.ps1`.

The repository-root `.dockerignore` limits IdentityGateway and Chat.Host image contexts to their project dependencies, protobuf contracts and the identity appearance asset; the chat Dockerfile copies `proto/`. The privacy handoff returns 404 for an account with neither a row nor tombstone; `Chat.Host.Tests/MailChecks.cs` checks that case through the contacts/mail fixture.

Account data keys and text mail: [owner decision](../decisions/BACK-account-data-keys.md) and [scope note](../decisions/BACK-guild-roster-scope.md#account-data-key-prerequisite-lane-c). `BackendServices/AccountDataCrypto/` owns the versioned AES-GCM envelope and counter rule. `IdentityGateway/{Schema.AccountDataKeys.sql,FileKekProvider.cs,PostgresAccountDataKeys.cs,Program.cs}` creates wrapped per-account keys, enforces a separate pinned-certificate internal HTTPS listener, audits one unwrap per key fetch, counts encryptions, supports KEK rewrap, seven-day erasure and restricted `identity_maint` 90-day audit purge. The authenticated privacy coordinator handoff is on `/v1/internal/privacy/accounts/{accountId}/erasure`; it rejects missing verification or hold values and accepts repeated tombstoned handoffs. Upstream must perform step-up, grace and fail-closed legal-hold checks. `Chat.Postgres/{Schema.Mail.sql,PostgresMailStore.cs}` and `Chat.Host/{MailKeyClient.cs,MailRoutes.cs}` own recipient-encrypted text mail, per-request key reuse, batched sender erasure checks and hourly ciphertext expiry. `IdentityGateway/Dockerfile`, `Chat.Host/Dockerfile`, and `IdentityGateway/ops/` provide the backend images, secret-file Compose delivery, decrypt unit and daily maintenance timer; `ops/steam-server/compose.yaml` remains game-only. `tools/Test-ChatContacts.ps1 -EvidenceRoot Artifacts/Persistence/ChatContacts/<fresh-child>` runs the focused contacts/mail PostgreSQL fixture including restricted maintenance; `IdentityGateway.Tests` covers the envelope. Owner/ops must provision systemd-creds, connect the privacy coordinator and replay external WORM tombstones before serving restores. InventoryLedger mail escrow is absent, so item/gold attachments remain follow-up.

Chat client bridge: `GameClient/Source/ShatteredFrontier/{Public,Private}/Chat/` owns a game-instance WebSocket subsystem and the unstyled WBP base. `ASFFrontEndController::DoEnter` passes the gateway session and selected character in memory; each connection requests a fresh `/v1/characters/{characterId}/contacts-ticket`, then authenticates at configured `USFChatSettings.Endpoint` (`DefaultGame.ini`). Blueprint sends and delegates cover party, whisper, incoming messages and relay statuses. Chat.Host returns `not_delivered` for blocked whispers without disclosing the block, `not_in_party` for nonmember party sends and `not_in_guild` for nonmember guild sends. The subsystem currently broadcasts party and whisper rejections; guild client presentation remains pending. Owner decision: player-facing block wording. Chat.Host rechecks guild membership through Guild.Host before each guild delivery. No zone channel exists.

The full Security login, progression creation saga and restore/purge are still pending. Use the pinned SDK for this project's tests and the owner migration tool for schema install.

Character POST retry receipt: `IdentityGateway/Schema.CharacterCreateRequests.sql` and `PostgresIdentityStore.CreateCharacter` commit the account-scoped request hash and original response in the character insertion transaction. Repeating a key with the same normalized request returns the original 201 response; changed input returns `IDEMPOTENCY_KEY_CONFLICT`, including after a later delete. Apply the identity owner migration and grant runtime `SELECT, INSERT` on `identity.character_create_requests` before starting this build. `IdentityGateway.Tests` covers canonical replay; `pwsh tools/Test-IdentityGatewayCreate.ps1` verifies the actual PostgreSQL migration, grants, concurrent create and restart replay without Unreal. This does not initialize progression or perform the designed starter grant; `active` remains the existing pilot behavior.
