# B-03 — bounded actor admission proposal

Status: owner-response draft, 2026-10-18. This concretizes [PER-01 authority/fencing](PER-01-authority-fencing-contract.md); it accepts no protected-domain changes, registers no RPC and enables no mutation handler. ## Recommended caller path and identities

Recommend **client → gateway → Building**, using validated token/proof and gateway-injected actor IDs. Building obtains exact live validation from the current World-selected zone through a proposed internal `ValidateConstructionIntent`; this returns facts, never actor identity or a general permission. The client cannot choose the validating server. Gateway does not decide geometry and the zone does not receive/replay a client credential. Backend/Construction must accept that gateway transports the player command while current-zone endorsement is mandatory. Without that amendment, this path stays disabled; direct zone → Building is the alternative requiring a Backend player-caller exception and an equally strong actor-binding interface.

Proposal: retain Backend's `spiffe://lsf.<environment>/<dc_region>/<service>` for gateway, Building, auth, Character, World and Inventory; server certificate adds exact `srvi_` URI SAN, checked against World enrollment. World/Security must select its canonical SAN encoding, issuing CA and registration mapping, resolving the conflicting World spelling before wire work. No third identity format, new signing issuer or forwarded bearer grant is introduced. Issuers remain the owning authenticated services; receipts are references verified directly with that service.

| Logical operation / recipient | Proposed caller allowlist and authority |
| --- | --- |
| Submit/preview/result / Building | `gateway` with current actor context; support result lookup remains existing separately authorized/audited path. Preview reserves nothing. |
| `BindActorIntent` / `auth-service` | `gateway` only after external token/proof validation; Auth verifies token/proof and records an opaque intent reference bound to the actor/realm/key/semantic digest. This reference reserves no right and is not independently usable without authenticated Building prepare. |
| `ValidateConstructionIntent` / World-selected zone | `building-service`; recipient must be current registered owner for realm/zone/layer/character. Response binds observed facts and its workload; World later reserves that same ownership revision. |
| `PrepareActorAdmission` / `auth-service`, `character-service`, `world-service` | `building-service` only, authenticated current coordinator delivery authority per B-04. Auth validates session/account/effective restrictions; Character validates ownership/active eligibility; World validates live ownership/allocation/no transit. These are new internal proposals, not calls to gateway-only `ValidateSession`. |
| `ReadActorAdmission`, `ApplyAdmissionDecision`, `CompleteAdmission` / those same authorities | `building-service` only for its fixed action participation. Read returns only this action's receipt/status. Apply/complete reuse Construction's immutable decision/certificate, never a separate commit protocol. |
| Existing material/terrain/geometry participation | Existing Construction owners and phases, with B-03 receipt references in prepared evidence; protected Inventory interface acceptance still required. |

## Exact logical records

All fields below are required unless marked optional. IDs use existing registry syntax; `operation` is a pinned construction operation, never caller-selected executable text. `Digest` means profile ID plus 32-byte digest; byte framing/versioning belongs to B-05. Revisions are positive signed int64 without reuse/wrap; World `uint64 owner_version` needs checked mapping or an approved wider representation. Timestamp precision, maximum sizes and enum wire values require B-05 approval; no production parser is implied.

| Record | Fields / immutable binding |
| --- | --- |
| `IntentContext` (pre-action only) | `realm_id`, scoped `idempotency_key` (≤128 chars), `quote_id`, `quote_digest`, `semantic_digest`, `account_id`, `session_id`, `character_id`, `operation`, `claim_id` (optional only for public/unclaimed operation), `zone_id`, `layer`, `content_version`, `config_version`. Excludes `action_id`, `participant_ids`, admission receipts and B-04 delivery fields: these are not caller-assignable. |
| `ActionBinding` (post-allocation; “Binding” below) | `IntentContext` + Building-assigned `action_id:cba_` and fixed `participant_ids`. The canonical server quote determines the proposed participant set before allocation; `semantic_digest` binds that set and exact intent under B-05. Building resolves the quote, fixes the identical set or rejects for re-preview; it never changes participants by changing the existing hash. Receipt digests never enter their own semantic hash. |
| `SubmitIntent` | `IntentContext` with gateway-derived actor IDs + `intent_ref`, exact intent payload/digest, expected geometry/claim/source revisions, correlation/causation. Exactly the pre-action exclusions apply; Building returns the assigned action ID after durable allocation, before grants. An unknown historical key cannot nominate a replacement action. |
| `BindActorIntent` / result | `IntentContext` + validated token/proof; Auth derives/checks actor IDs against credentials → `intent_ref`, exact context binding digest, `created_at`. Exactly the pre-action exclusions apply to request/result. Gateway forwards the opaque reference to Building; no token/proof goes to Building/zone. Rebinding an existing key to changed context rejects. |
| `ZoneValidationRequest` / `ZoneValidationReceipt` | Binding + exact geometry keys/bounds/expected revisions; receipt adds `validation_ref`, `issuer_srvi_id`, authenticated workload reference, `allocation_ref`, `allocation_epoch`, `owner_version`, observed actor/geometry revisions, reach/LOS/occupancy/support/budget validation digest, `observed_at`, receipt digest. Observations alone reserve nothing. |
| `PrepareActorAdmission` | Binding + recipient `participant_id`, B-04 incarnation/generation/worker/phase/payload binding, Building action deadline, predecessor receipt references/digests, zone receipt for World. Auth additionally receives `intent_ref`, scoped `idempotency_key`, `quote_digest`, verifies its exact recorded actor/key/digest/operation/quote binding, and atomically associates it with this action while granting; reuse by another action rejects. Forwarding actor IDs alone is insufficient. |
| `AdmissionReceipt` | Binding + `receipt_ref`, exact issuer service/workload, fixed recipient/coordinator, `participant_id`, state, owning authorization revisions, `prepared_digest`, `prepared_at`, predecessor digests. Auth adds session/account/effective-restriction revisions; Character adds account-owner/eligibility revisions; World adds server/allocation/owner revisions and zone validation digest. State is `prepared`, `aborted`, `applied_commit`, or `completed`; terminal receipts add original decision digest and optional completion digest. |
| `ReadActorAdmission` / result | Binding + recipient and B-04 delivery authorization → state/receipt or authenticated `absent`. Absence is not authorization, proof of abort, or permission to recreate after a terminal tombstone. |
| `ApplyAdmissionDecision` / `CompleteAdmission` | Binding + B-04 delivery binding + original immutable decision/prepared set; complete additionally carries all-applied completion certificate. Response: admission state, immutable applied/completed digest. Authority-only participants attest resolution; they issue no economic result. |
| `AdmissionError` | Canonical gRPC status + `ErrorInfo(domain=lsf.<recipient>, reason, metadata={correlation_id, action_id?, safe_detail})`; optional standard `RetryInfo`. Proposed reasons: `ACTOR_INVALID`, `OWNER_CHANGED`, `IN_TRANSIT`, `REVISION_CONFLICT`, `IDEMPOTENCY_MISMATCH`, `AUTHORITY_PENDING`. Never disclose session/restriction detail or unrelated sources. |

Map malformed fields to `INVALID_ARGUMENT`; absent/invalid mTLS or gateway context to `UNAUTHENTICATED`/`PERMISSION_DENIED`; valid but ineligible/transit/stale state to `FAILED_PRECONDITION`; changed existing action/hash to `ALREADY_EXISTS/IDEMPOTENCY_MISMATCH`; concurrent revision conflict to `ABORTED`; unavailable owner to `UNAVAILABLE`. Lost replies/timeouts mean pending and same-key reconciliation, never an implicit denial, release or refund. A client-safe response is `pending`, `aborted` or `completed` with permitted receipt fields; commit alone cannot return completed.

## Linearization, lifetime and recovery

Recommend **per-authority grant-wins for the exact immutable action**, including partial admission: if Auth prepares before logout/revocation, that action may acquire later Character/World/material grants and commit within the existing undecided deadline even after the session ends. Revocation prevents every later Auth grant immediately at its owning serialized transition; it does not cancel an earlier grant. This is a deliberate pending Security policy, not implied by session caches or a transport fixture. Character eligibility transitions follow the same local rule; later independent authorities can still deny their grants, causing the sole Building abort.

An immediate-cancel-before-decision alternative requires a serialized cancellation/decision fence and a proven cross-authority ordering, including partial grants and lost replies. A final remote session lookup before Building commit cannot supply that atomicity. If Security requires immediate cancellation, reject this recommendation and keep admission disabled until that alternative is fully designed; never silently treat a stale grant or TTL as the cancellation mechanism. Persisted commit always rolls forward under either policy.

| Phase / durable local record | Atomic transaction / concurrent lifecycle rule |
| --- | --- |
| Building pending | Unique scoped key/action/hash and fixed participants; deadline uses existing five-real-second undecided boundary. No grant or material effect yet. Failed/late preparation leads to sole durable abort. |
| Auth prepare | Serialize grant insertion and session/account eligibility/revocation revision checks on the owning durable rows; store receipt and publication record atomically. `EndSession`, superseding login and `RevokeSessions` use that same serialization. Security must define how effective enforcement restrictions enter this ordering; a separate cached `CheckRestrictions` hint cannot satisfy it. |
| Character prepare | In one local transaction, check account ownership/active state and store action-bound eligibility fence + receipt; deletion/realm transfer/ownership changes serialize with this fence. Redis presence is advisory; World is simulation authority. |
| World prepare | Atomically compare current registered server, allocation epoch, character owner/no transit and matching zone evidence, then persist a durable simulation fence + receipt. Recommend a World-owned durable admission gate through which registration loss, reassignment and handoff transitions must also serialize; exact PostgreSQL/Redis recovery bridge is pending World input. No Redis-read-then-PostgreSQL-write shortcut. |
| Building/Inventory/World geometry prepare | Preserve Construction claim/permission/source/geometry fences. Transfer/revocation/cache destruction wins first and invalidates prepare, or waits behind prepared fence. Inventory independently validates all sources, automatic supply, exact lots/owners/beneficiaries and all-or-none holds. |
| Partial admission / unknown reply | Persist grant before acknowledgement; retries read same record. If later grant fails, Building records abort and delivers it to every fixed participant, including absent ones, which retain terminal tombstones to reject late prepares. Never release a prepared grant because another participant is missing or a transport deadline expires. |
| Decision / completion | Building writes one immutable commit/abort only; commit requires every fixed prepared digest. Authority-only apply records decision acknowledgement; complete releases its fence only after matching all-applied certificate. Abort releases without gameplay activation. Every state/receipt/outbox effect is one owning transaction and checks B-04 authority. |
| Handoff / server loss | Once World grant wins, recommend deferring `RequestHandoff`/owner flip until abort or completion; a transit transition that wins first denies prepare. Lost server can be marked unavailable immediately, but replacement cannot cross unresolved simulation fence. Recovery uses service authority without requiring original zone/session. This may exceed the 300ms target and World’s current PostgreSQL-outage independence: explicit World acceptance required. |
| Recovery / disclosure | Durable grants/holds survive process loss, logout, revocation and expired quotes. B-04 enrolled incarnation/current delivery identity recovers the original action; no new actor grant is requested to finish commit. A new valid gateway session must independently establish current account/character access before private result disclosure. Historical grants cannot authenticate login, new commands or result reads. |

No network calls occur inside local DB locks. Authenticated owner reads occur before locks; only owning durable reservations and local phase/B-04 checks protect later effects. Retain receipt/tombstone references while action/ledger/geometry/archive dependencies remain, under owning privacy/hold rules; generic seven-day dedup or TTL expiry is never the durable fence. B-04 alone defines delivery takeover, barriers and restore admission; B-03 adds no second generation or issuer.

## Failure vectors and owner responses

| Required fixture / race | Expected evidence |
| --- | --- |
| Forged gateway headers, wrong server, stale allocation/owner, in-transit actor | Reject before new material reservations; authentic workload alone grants no actor/claim rights. |
| Auth grant vs logout/revocation on either side; only Auth granted at revocation | Earlier grant remains valid only for same action; later grant denied. Later admission may succeed or cause sole abort; no new command or private disclosure to ended session. |
| Claim/source revocation vs prepare; World grant vs handoff/owner loss | Exactly one local ordering; no invalidating transition crosses durable prepared fence; competing action waits or preparation rejects. |
| Lost grant reply, crash between authorities, delayed prepare after abort | Same action/digest, recoverable partial records, terminal tombstone rejects recreation; no timeout release or double charge. |
| Revocation after commit; zone dies; replay after generic cache age | Original decision rolls forward through B-04 service authority; withheld outputs require matching completion; result access checked anew. |
| Forged or mixed receipts; restriction bridge unavailable; World Redis/durable state disagrees | Fail closed/pending; no mixed actor/hash/participants, no fresh grant from replica/cache or guessed larger epoch. |
