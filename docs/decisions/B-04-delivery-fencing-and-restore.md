# B-04 — delivery fencing and restore enrollment

Status: proposed for owner review, 2026-10-18. Markdown contract only; no accepted RPC, schema, protected-owner change, live action or B-04 closure. Choose a per-action durable receiver barrier plus explicit restore enrollment. Remote lookup alone has a read/write race; a process lease alone cannot fence participant writes; cross-domain transactions violate ownership. These are release-bound safety rules, not console tuning; performance remains to be measured in an isolated fixture.

## Proposed logical messages and storage profile

Names below are logical operations, not registered endpoints. B-05 must assign protobuf fields/encodings and vectors before implementation. Reject unknown enums/profiles and oversized/duplicate fields before mutation; never truncate IDs. Proposed bounds are fixed release limits, subject to owner acceptance.

| Field / type | Binding and bound |
| --- | --- |
| `realmId`, `actionId` | Exact registered realm string (1–64 UTF-8 bytes proposed); `cba_` plus 26-character Registry ULID. No client-created replacement action on recovery. |
| `semanticProfile`, `semanticHash` | Registered profile string 1–64 ASCII bytes; 32-byte SHA-256. Original semantic intent remains invariant across delivery/enrollment; no circular inclusion of later evidence. |
| `originIncarnation`, `deliveryIncarnation`, `enrollmentRef` | Opaque 16-byte incarnation values; immutable creation origin versus explicitly enrolled delivery scope. Enrollment reference is 32 bytes identifying the approved manifest, not a new Registry entity prefix. Values have no ordering or authority merely from randomness. |
| `deliveryGeneration`, `worker` | Positive signed int64, initially 1, no wrap/reuse; worker is existing authenticated Building SPIFFE identity (≤256 bytes) plus attested per-process instance reference (≤128 bytes). Same generation binds exactly one instance. Service name alone cannot distinguish replicas; exact attestation mapping is an open Backend/Security interface. |
| `participant`, `fixedParticipants`, `fixedSetDigest` | Exact registered service identity plus release-declared role (≤64 ASCII bytes each), unique sorted set of 1–32 proposed entries, 32-byte digest. Include Building geometry and every required authority-only participant. Role IDs and maximum require Registry/domain acceptance; never silently omit overflow participants. |
| `phase`, `payloadProfile`, `payloadDigest` | Closed enum `BARRIER, PREPARE, APPLY_COMMIT, APPLY_ABORT, COMPLETE, QUERY`; registered profile ≤64 bytes and 32-byte digest of exact recipient-specific phase payload. Query has its declared empty payload. Domain payload limits remain owning-contract limits. |
| `decisionEvidence`, `completionEvidence`, receipts | Immutable origin identity/digest, original decision generation/worker, fixed set and sorted participant→prepared digests; completion adds decision digest and every applied digest/result digest. Lists bounded by fixed set; digests 32 bytes, references ≤128 bytes. No unrelated inventory/private contents. |

All operations bind the common action/hash/profile, origin, enrolled delivery incarnation, generation/worker, recipient and fixed-set digest. Existing ≤128-character generic RPC keys are deterministic per action/incarnation/generation/recipient/phase/step; exact bounded derivation belongs to B-05. Backend's generic hash covers the request with only its key cleared, including delivery fields; it changes with generation. Semantic hash does not. Phase payload digest and immutable receipt digest have separate registered domains/profiles. Generic cache replay cannot bypass current fencing checks or replace retained action identity; seven-day cleanup cannot remove protocol tombstones/evidence.

**Lookup request:** receiver-authenticated request to authoritative Building for the exact common tuple, requested phase and payload digest. Building returns `CURRENT` with exact tuple, current action state, enrollment gate, allowed phase and required immutable evidence; otherwise `STALE`, `NOT_PARTICIPANT`, `CONFLICT`, `RECOVERY_PENDING` or `UNKNOWN`. Read the authoritative primary, never a replica/cache. Lookup is direct authenticated evidence, not a forwarded bearer permit. An absent authoritative action returns `UNKNOWN`; it cannot authorize record creation, abort, or a guessed decision.

**Barrier request/ack:** current worker requests `BARRIER`; receiver independently verifies lookup before locking. Durable ack contains exact admitted tuple, local state/revision and all existing prepared/applied/completed/aborted evidence. Even for an absent record it returns a durable `EMPTY` identity tombstone, not `NOT_FOUND`. A repeated same-generation/same-worker barrier returns current receipts without resetting state. Authenticated `QUERY` is read-only; it reports absence but never infers a negative vote or creates authority.

**Phase response:** `APPLIED_ONCE`, `REPLAY`, `FENCED`, `CONFLICT`, `RECOVERY_PENDING` or `UNKNOWN`, with admitted tuple/state and permitted immutable receipts. Proposed wire mapping: malformed input→`INVALID_ARGUMENT`; unauthenticated/wrong caller→existing authentication/permission errors; stale generation/incarnation/phase→`FAILED_PRECONDITION`; changed identity/hash/payload→`ALREADY_EXISTS` mismatch; concurrent CAS loss→`ABORTED`; missing authority→`UNAVAILABLE`; contradictory durable evidence→`DATA_LOSS`. Logical `UNKNOWN` is not business success; timeouts/ambiguous commit replies require query/reconciliation. Register reasons and mappings before wire release.

Receiver uniqueness is `(realmId, actionId, originIncarnation)` plus retained action-ID association preventing reuse under a different origin. Store immutable semantic identity/fixed set, admitted delivery tuple, enrollment reference, revision, state `EMPTY/PREPARED/APPLIED/ABORTED/COMPLETED`, evidence and pending delivery. An aborted empty record is terminal; missing prepare is explicitly represented, never fabricated as a prepared digest. Persist exact evidence bytes/references durably enough for the supported restore horizon; receipts cannot be overwritten by a newer barrier.

## Local transaction predicates and phase rules

1. Building allocates the action/fixed set before any prepare. Initial receiver record creation requires generation 1, authenticated matching current lookup and admitted enrollment. Once recovery advances a generation, absence admits only a barrier; that barrier creates the identity tombstone before any phase. No DB lock is held during lookup, proof verification or interservice calls.
2. Building takeover locks its action and CASes `(enrolled deliveryIncarnation, generation, worker, revision)` to `(same incarnation, generation+1, replacement worker, revision+1)`, marks recovery pending and retains decisions/receipts. Overflow closes recovery without increment. Every decision/progress/completion/outbox authorization write rechecks that tuple and the relevant action state in its local transaction; a stale worker loses. A response received after a newer takeover cannot count toward that newer worker's barrier set.
3. Receiver locks/upserts the same identity record, verifies enrolled manifest/mapping is still locally admitted, exact hash/profile/fixed set and recipient membership, then CASes its revision. Compare generations only within the same admitted delivery incarnation: lower rejects, same generation/different worker conflicts, higher changes the tuple only through a verified barrier. For an explicit staged old→new mapping, the first verified new-incarnation barrier instead CASes the expected old tuple/enrollment reference to `(new deliveryIncarnation, 1, approved worker, new enrollmentRef)`, preserving origin, phase state and every receipt/hold; no numeric comparison crosses incarnations. Ordinary phases cannot perform this transition. Enrollment gate and row predicates are checked atomically with effects, receipts and local pending work; process memory is insufficient.
4. Every phase transaction requires stored delivery tuple equal to the verified request, matching phase/payload and compatible local state. Within one admitted delivery incarnation, a lower-generation lookup followed by an old phase may commit **before** the receiver's replacement barrier and must appear in its ack; **after** that barrier, the old phase rejects. A stale intermediate barrier may install before a later barrier; replacement waits for its own exact tuple at every participant. Across restore incarnations the freeze/enrollment gate additionally rejects old delivery before the new barrier. Neither an ordinary phase nor staging alone switches the active tuple. This is a receiver linearization point, not instantaneous global revocation.
5. After takeover, require matching durable barriers and reconciled receipts from the whole fixed set before any additional prepare/reservation, decision or completion. Barrier/query never wait for admission votes. Remaining prepares follow B-03's acyclic acquisition order; an unavailable participant keeps recovery pending. Already durable decision/completion may be transported only after current barriers reconcile, under current delivery authority and unchanged historical evidence.
6. `PREPARE` requires an undecided action lookup, owning authorization/revisions/fences, and `EMPTY` or exact prepared replay. `ABORTED/APPLIED/COMPLETED` reject prepare; delayed stale lookup cannot recreate a locally terminal action. If prepare wins locally before abort arrives, abort releases that exact reservation once. No hold expires from a delivery timeout.
7. `APPLY_COMMIT` requires authoritative immutable commit, membership and exact local prepared digest; atomically apply once, retain held output/projection gates and record applied receipt. Commit on `EMPTY` or a missing restored prepare is recovery pending for owner reconstruction, not an invented no-op apply. `APPLY_ABORT` requires immutable abort; release only own uncommitted hold, record terminal abort even on `EMPTY`. Commit/abort disagreement is an invariant incident; never convert an applied commit to abort.
8. `COMPLETE` requires immutable commit and all-fixed-participant applied certificate, exact local applied receipt and membership. Release only its exact held outputs/geometry once and persist completion receipt; replay returns it. Barrier or partial participant acknowledgment grants no activation. Read/occupancy gates remain until coherent projection is safe. Historical decision generation need not equal delivery generation.
9. Building may abort an undecided action only after matching barriers/reconciliation and its existing authoritative five-second deadline check using DB UTC **after** acquiring the row lock; absence in a restored snapshot is not proof of undecided state. Takeover during decision/completion preserves whichever write won Building's CAS; a lost reply queries that immutable evidence. Prepared-without-trustworthy-decision remains fenced.

## Restore enrollment progression and verifier ownership

Scope is a named incident/environment/region/realm, affected owning stores and explicit action/frontier manifest. The manifest binds old enrollment, new delivery incarnation, source backups/WAL, schema/build/content/profile support, action/receipt/event/inbox/DLQ/dedup frontiers, erasure/hold evidence, approved recovery phases and fixed participant sets. It contains an explicit per-action `originIncarnation → new deliveryIncarnation` mapping (including digest identity); no wildcard adopting unknown old actions. Multi-hop recovery retains the original origin and chains prior enrollment references. New actions receive the newly enrolled creation origin only after reopening.

| Durable progression | Required verifier and transition evidence |
| --- | --- |
| `FROZEN` | Named incident commander/LiveOps maintenance authority gates affected admission, consumers and activation; persistence owners inventory all writers, restores and frontiers. Unaffected scopes require explicit isolation proof. |
| `FENCED` | Operations proves old DB primaries/storage writes cannot resume; Security proves old workload credentials and queued/network delivery cannot mutate; World proves affected server/allocation ownership is drained/fenced. Evidence is recorded outside the restored snapshots' rollback boundary. A certificate expiry, random UUID, DNS change or stopped process alone is insufficient proof. |
| `STAGED` | Each affected domain's verifier authenticates the approved manifest via existing operations authority, checks prior enrollment and local scope, then CASes its enrollment gate to the named pending replacement. Persist proof references/mapping before replying; staging neither erases nor switches an action's active delivery tuple. Compare opaque identities only for exact equality. The first mapped barrier performs the atomic action-tuple transition in rule 3, starting new-incarnation generation 1 without comparing old/new integers. |
| `RECONCILING` | All scoped domains acknowledge staged enrollment; only manifest-authorized barrier/query/recovery phases may run. Reconstruct authoritative decision/receipt frontier, replay erasure, reconcile downstream effects, then install new-incarnation barriers. Preserve original evidence; absent or contradictory history blocks that action/scope. No new decisions until the manifest proves the authoritative undecided frontier; no guessed abort/refund. |
| `OPEN` | Persistence/domain owners attest action/material/geometry/dedup coherence and compatible readers/writers; Security attests erasure/authority; World attests allocations/readiness; incident commander authorizes reopening. Each receiver persists the same approved open revision before ordinary phases; partial/unreachable enrollment stays closed. |

During staging/reconciliation, reject old-incarnation delivery even with a greater generation; admit mapped historical evidence only through approved current delivery. A previously verified old packet also checks the locally changed enrollment gate inside its effect transaction. Lost enrollment reply retries the same manifest/reference; same manifest is idempotent, competing manifests or missing prior lineage conflict. Failure midway never reopens a subset implicitly. Failed restore requires another externally fenced enrollment transition, not rolling the enrollment table backward.

Missing protected operations interface: owners must define authenticated proof submission/readback, incident approver identities, old-primary fence verification, exact workload-instance attestation, scope/mapping validation, durable externally surviving evidence storage and compare-and-set enrollment at **every** writer. This draft specifies obligations, not an implemented API or new signing issuer. Security/LiveOps/Character/Itemization sources remain read-only. A restored copy cannot vouch for its own fence; missing external evidence blocks enrollment even if all local rows look consistent.

## Named race cases and owner acceptance

Every case asserts stable action/hash, immutable evidence, conserved materials and no usable incomplete outputs or mixed geometry. These are required fixture cases, not executed DB/security proofs.

| Case | Required outcome |
| --- | --- |
| `F01 ABSENT_BARRIER_LATE_PREPARE` | Empty barrier tombstone rejects delayed lower-generation prepare; abort-on-empty remains terminal. |
| `F02 LOOKUP_BEFORE_AFTER_BARRIER` | Old apply before barrier appears once in ack; after barrier rejects, including stale intermediate lookups. |
| `F03 SAME_GENERATION_WORKER` | Same worker barrier retries return receipts unchanged; different worker/forged higher generation reject. |
| `F04 DELAYED_ABORT_PREPARE_RECOVERY` | Abort cannot replace commit; terminal abort rejects prepare; stale recovery writer loses CAS. |
| `F05 TAKEOVER_COMMIT_COMPLETION` | Winning durable decision/certificate preserved through lost replies/new takeovers; later delivery uses new tuple and original evidence. |
| `F06 UNAVAILABLE_OVERFLOW` | Missing lookup/participant/ambiguous reply stays pending; int64 max cannot wrap or authorize another worker. |
| `F07 RESTORE_OLD_WRITER_PARTIAL_ENROLLMENT` | Unfenced old primary/workload or missing external proof blocks stage; old-incarnation calls reject; partial enrollment stays closed. |
| `F08 RESTORE_FRONTIER_GAP_MAPPING` | Unknown origin/action, missing prepare/decision, contradictory receipts or unsupported format blocks recovery; no new UUID/abort/refund repairs history. |
| `F09 STALE_LOOKUP_ENROLLMENT_CAS` | Old lookup races enrollment: effect before frozen gate is recorded/reconciled; after gate fails local CAS; old manifest retry cannot overwrite newer enrollment. |
| `F10 FIRST_RESTORE_BARRIER_RESET` | Given an old tuple at generation 100, staging preserves it and blocks ordinary phases; the first authenticated manifest-mapped new-incarnation barrier CASes it to generation 1/new worker while preserving origin/state/receipts/holds. Same barrier retry replays, old-incarnation generation 101 rejects, an unmapped incarnation or ordinary-phase tuple switch rejects; subsequent generations compare only inside the new incarnation. |

Each acceptance record must name authority, date, artifact revision, scope-approval versus closure stage and exact evidence; independent review or model exploration is not acceptance. Independent review must follow this draft and address the named cases. Revisit if an authority cannot serialize its transition, proof cannot survive rollback, supported participant count exceeds bounds, or an old build cannot recover retained evidence. No runtime tests are required for this documentation-only proposal.
