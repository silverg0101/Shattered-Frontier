# SBX-06F: development construction snapshot codec

This independent numerical/format task may run alongside SBX-06E authority. It does not read/write disk or mutate actors. Local publication and staged world import remain separate gates. Use Core's bundled BLAKE3, no dependency/environment change.

## Typed snapshot and API

New `FSFConstructionSavedCell { FIntVector Cell; int32 Shape; int32 Rotation; }`, `FSFConstructionSavedDoor { FIntVector OriginCell; int32 YawQuarterTurns; bool bOpen; }`, and `FSFConstructionSandboxSnapshot { uint64 SourceRevision; TArray<...> Cells; TArray<...> Doors; }`. Defaults are zero/empty/closed. Namespace `SFConstructionSaveCodec` supplies `Encode(const Snapshot&, TArray<uint8>& Out)` and `Decode(const TArray<uint8>&, Snapshot& Out)`, false preserving output on every invalid input. Canonical successful records are sorted by X/Y/Z separately per kind; duplicate cell addresses or duplicate door origins reject. Never serialize weak actors, paths, permissions, mass, clocks, confirmations or retry state. SourceRevision is informational provenance; future import publishes current revision+1 and never trusts it as authority.

Limits: cells<=4096, doors<=64, complete encoded input<=65,536 bytes. Structural record coordinates must be X/Y[-20,20), Z[0,20); shape0–2, rotation0–23. Door origins have the same initial coordinate bounds; yaw0–3 and the yaw-transformed2×1×4-cell envelope must fit the plot/height, as in SBX-06D/E. Validate raw coordinates before offset arithmetic. The codec validates syntax/content compatibility only: actual support, reservations, clearance, player occupancy and environment must be revalidated by State on import. Valid codec data is not permission to construct floating solids.

## Frozen v1 binary layout

All integers are unsigned little-endian except coordinates encoded as two's-complement signed32, with explicit byte operations rather than ABI struct packing/host archive versions. In order:8-byte ASCII magic `SFCSBX01`; uint32 format1; uint32 provenance1 (unlimited development only, all other bits/values reject); uint64 SourceRevision; uint32 CellCount; uint32 DoorCount. Then exact UTF-8 identity bytes `greenlands-construction-sandbox-v1\0rough-timber-v1\0sandbox-rough-timber-door-v1\0` (include the three explicit NUL separators, no extra implicit terminator), followed by three64-byte lowercase ASCII canonical geometry payload SHA256 values in shape0/1/2 order, obtained from the current canonical geometry builder. This content block is fixed by the release; unknown identity/hash rejects.

Then all cell records, each14 bytes: int32 X/Y/Z, uint8 shape, uint8 rotation. Then all door records, each14 bytes: int32 X/Y/Z, uint8 yaw, uint8 open0/1. Finally32 raw BLAKE3 bytes over the entire preceding data. No trailing data, optional fields, arbitrary strings or native padding. BLAKE3 is corruption detection, not authentication. Validate byte cap and header/count bounds before computing sizes/allocating record arrays, verify exact total length/digest, then parse into a temporary snapshot and publish only after all validation. Encode canonicalizes order; Decode accepts valid record order and returns canonical order. Avoid signed overflow and unchecked count multiplication.

## Assignment and tests

Luna/medium owns only new `SFConstructionSaveCodec.h/.cpp` and `SFConstructionSaveCodecTests.cpp`. No disk/world/State/input/docs/build/commit changes. Parent owns architecture/builds and separate Sol/medium reviewer checks source/raw evidence. Assert existing output contents are preserved. Keep tests guarded like existing editor/development tests. Do not mirror every implementation line with trivial tests.

## Publication/import follow-up

Prefer immutable numbered generations under an internally derived fixed `ProjectSavedDir()/ConstructionSandbox` root: write a uniquely owned pending file, flush/close and validate, then publish by a same-directory rename to a new nonexisting final generation name. Never delete/overwrite the previous committed save to publish another. Bound directory scanning/retention and handle competing publication without replacing a winner. The installed generic Move(Replace=true) deletion path is unacceptable; this scheme deliberately avoids replacement. Prove crash-before-publication leaves the prior generation, malformed latest saves preserve the live world, and process restart reproduces validated content. Do not claim power-loss or production recovery guarantees.

Future save/export rejects unstable/due-wave assemblies so restart cannot reset support-loss grace. Import must stage all current-version members/door projections, recompute support/attachments/reservations/clearance against the actual world while excluding only the old replaced owned projections, then atomically publish one fresh assembly revision. No disk or authority acceptance is claimed by this codec assignment.

Source check for later publication (2026-10-18): Microsoft [MoveFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefilew) requires a nonexisting destination; [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) documents failure modes that can rename/remove the old name. Immutable generations are a design choice inferred from those behaviors and the installed UE helper implementation, not evidence of power-loss durability. Test the exact publication implementation before accepting it.
