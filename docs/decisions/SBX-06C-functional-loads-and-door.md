## First bounded assignment: support input extension

Add an authority-supplied nonnegative `AttachedLoad` to each support member, default0, in the existing abstract load unit. It represents the sum of versioned functional-object shares assigned to that member, not geometry or player-supplied mass. Validate finite0–1,000,000 load units per member, consistent with the solver's existing numeric input bounds; invalid input preserves output. Initialize node load as `profile weight * occupied fraction + attached load`, then use the unchanged frozen contact DAG, load/reach, capacity equality and failure closure. An attachment does not become an anchor, add reach, change contact area, reroute a failed share or receive a health discount. Defaults must reproduce existing results.

Luna/medium owns only `SFConstructionSupport.h/.cpp` and a new focused `SFConstructionFunctionalLoadTests.cpp`. Cover default equivalence, exact added load and inherited parent load, area-proportional parent shares, equality/overload on anchored and non-anchor members, failed-parent propagation, input ordering, negative/NaN/infinite/over-bound rejection and preserved output. No caller accepts functional objects yet. Parent owns formula clarification, integration/build and shared documents; separate Sol/medium reviews source and evidence.
