## API and operating rules

New non-UObject `FSFConstructionSaveStore` with default constructor and `bool Publish(const FSFConstructionSandboxSnapshot&, uint64& OutGeneration, FString& Reason)` / `bool ReadLatest(FSFConstructionSandboxSnapshot&, uint64& OutGeneration, FString& Reason)`. No public path argument. Root is internally derived, normalized absolute `FPaths::ProjectSavedDir()/ConstructionSandbox`. Constructor captures validated typed USFConstructionSandboxSettings: SaveGenerationsToRetain default3/bounds2–16 and SaveDirectoryEntryLimit default128/bounds32–512. Reviewed release authors only; effective on new store instance, no live/console override. Parent owns those settings fields/validation. File-format byte/count caps remain code invariants, not adjustable console limits.

Encode before filesystem mutation. Operations require the game thread in this synchronous pilot. ReadLatest is read-only and must not create folders. A missing/empty store returns false preserving snapshot/generation. Invalid configuration/root/enumeration, malformed latest data or any unsuccessful publication preserves output data/generation; Reason explains failure. Snapshot SourceRevision remains provenance, not an authority revision.

## Generations and publication

Published names are exactly `generation-` +20 zero-padded decimal digits for uint64 generation1..MAX +`.sfcs`. Scan only the root directory with a visitor stopping at the captured entry limit (all entries count, including unrecognized files/directories); never recurse or accumulate an unbounded FindFiles result. Strictly parse/canonicalize names with overflow-safe arithmetic; never use an enumerated arbitrary name as an output/delete path. Unknown names, pending files and directories are not saves and are never cleaned as old generations. Refuse overflow when next generation cannot be represented.

Publish creates the root only after valid encoding/scanning. Write to a fresh GUID-based `.pending-<digits>.sfcs` in that same directory; refuse an existing pending name. Check the complete write, Flush(true) and close, then read/Decode that pending file before publication. Reject oversized input before allocation. Rename to the next new final generation with replacement DISABLED; never delete/overwrite a prior final or a competing winner. A same-directory non-replacing platform move is required; generic Move(Replace=true) is forbidden. Close handles before renaming. All data is written before a final filename is exposed. This is bounded local publication, not power-loss or production durability acceptance.

Only after successful publication, prune strictly recognized older generation names to the captured retention count, keeping the newest versions. Retention failure does not undo a published save or report publication failure: return true with its generation and an explicit cleanup-deferred Reason. A future bounded scan may safely refuse an overfull store. Failed writes/renames clean only this attempt's owned pending file; an injected crash-before-publication may deliberately leave a pending file, which reads ignore. Never delete unknown files or perform recursive cleanup.

ReadLatest chooses the highest recognized generation and decodes exactly that bounded file; corrupt latest data rejects without silently selecting an older version. Explicit recovery UX can come later. Competing publishers choosing the same generation cannot overwrite one another; the loser preserves the winner and its own outputs. Retention must never remove the generation just published, even under a competing writer. Do not claim multiwriter sequencing or transactional world import from this helper.
