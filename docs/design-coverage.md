# Concept-to-design coverage

DOC-01 baseline: 2026-10-17; DOC-06 bounded follow-up: 2026-10-18. Scope: documentation only. [Work plan](design-work-plan.md) owns follow-up priorities; [backlog] owns implementation tickets. The [concept](../concept.md) is the vision, not an implementation acceptance contract.

## Reading the matrix

**Specified** means the cited inspected section defines the bounded behavior or acceptance stated in that row; it does not certify the whole domain. **Deferred** means planning explicitly excludes that behavior from the current slice. **Unresolved** names an existing decision or a concrete discrepancy. **Uninspected** means an owner/reference is mapped but detailed coverage was not verified. A row can have different states for its MVP subset and later ambition. No runtime, engine, capacity, price or hosting verification was performed.

E1 = engine/movement; H2 = persistent housing/terrain; G3 = small-group alpha; C4 = capacity/final MVP; VS = vertical slice. These labels follow [backlog], “Priority and milestone vocabulary.” Later roadmap phases are not newly authorized work. Reserved domain documents were read only.

No selected E1/H2 task requires inventing these later modes. No domain specification was rewritten: reserved owners retain their decisions and write boundaries. COV-01/02 remain later event-owner requests.

It is not a whole-spec audit: beyond the explicitly sampled Analytics, Security and Dungeon sections above, protected-domain detail, most progression/item/recipe content, complete PvP/crime/social modes, offline simulation and expansion content remain uninspected. Domain entry mappings alone do not establish completeness. Scope exclusions are not defects.
