## 10-npc-dialogue — FAIL

A player recognises the design: the opaque slate board with brass window frame, portrait and name plate, four numbered key-cap rows with moss selection, inset quest card with art well, Objectives/Rewards rules, brass Accept and outline Decline, synced tracker, HUD dimmed 40 %. It fails on two items: the key-cap numerals are still 13 px regular where the concept has 22 px bold (a section 2 type miss of 9 px on the most repeated element of the left column), and the speaker's head sits below the framing target in all three frames. Two further misses do not block on their own (card fill, disabled label contrast). Everything else is on tolerance or a canonical-style flag.

### 1. Key-cap numerals are 13 px regular, not 22 px bold
- **What's wrong:** live "1" ink 6x13 px (lum 244) inside the 52 px cap; concept 11x22 px (lum 255, bold). "2"-"4" the same. At 1:1 the caps read as blank brass squares with a small mark; the concept's numeral fills 40 % of the cap. The committed `GameClient/ArtSource/UI/Kit-v5/keycap_1.png` (106x108) carries a 16x28 px numeral at 2x, so the art batch did not change the numeral size (r23 item 4 open). `build_structures.py` lines 164-175 draw it with `EBGaramond-Regular` at `round(h*.58)` = 63 px, which measures 40 px tall for "1" in that face; the committed 28 px numeral did not come from those values, so rebuild and check the PNG, not only the capture.
- **Fix type:** SHARED (Kit-v5 art, Codex; UI v5 session owns the piece).
- **Instruction:** `GameClient/ArtSource/UI/Kit-v5/build_structures.py` line 164 `font_path = ... "EBGaramond-Bold.ttf"`; line 173 `ImageFont.truetype(str(font_path), round(h * (.43 if len(label) > 2 else .65)))` (EB Garamond Bold "1" = 0.63 em, so 70 px gives 44 px ink at 2x); keep `stroke_width=1`. Verify in the PNG: ivory ink of "1" 44 +-2 px tall, "2"-"4" 44-46 px. Rerun `Process-KitV5.py`, `Import-HudKit.py --save`, recapture. Acceptance: live numeral ink 22 +-1 px tall, max lum >= 250, cap plate still 53x54 at (529,469).

### 2. Speaker's head is below the framing target
- **What's wrong:** head centre y 35.3 % (open), 34.3 % (more), 34.5 % (accepted); x 14.5-15.4 %. Target x 15-25 %, y 24-34 %; concept x 21 %, y 27 %. The head sits level with the speech line (y 341-390) instead of the portrait's upper half; the figure stands in the strip between the screen edge and the board with its hand at x 436 (board edge 486). `DialogueHeadAboveCentreDegrees=14` (tooltip: "y ~32 %") measures y 34-35 % at `DialogueArmCm=230`. Posture is out of scope.
- **Fix type:** CODE (Engineer; config values).
- **Instruction:** `GameClient/Config/DefaultGame.ini` line 25 `DialogueHeadAboveCentreDegrees=18.0` (clamp 0..25; at the capture's vertical FOV about 0.6 deg per 1 % of screen height, so +4 deg should lift the head 5-7 %; confirm with one capture) and line 24 `DialogueFramingYawDegrees` in 4 deg steps from 34 until head centre x reads 18-22 % (one capture per step). Update the tooltip in `SFE1Settings.h` line 102 to the value that measures. Acceptance: head centre x 15-25 %, y 24-34 % in all three frames, nothing of the speaker cut by x 0, player mesh hidden.

### 3. Quest card has no inset fill
- **What's wrong:** card interior (23,35,42) = board fill; concept card (15,21,24), dE 5.3. The concept's right half reads as an inset darker panel; live it is the board colour inside a hairline. `SFDialogue.cpp` line 305 passes `Hex("0F1517")` as `KitPanel`'s `Fallback`, which only draws when the art is missing; `detail_card_frame` has an open interior.
- **Fix type:** CODE (Engineer).
- **Instruction:** `SFDialogue.cpp` line 305: before the `KitPanel`, add a `UBorder` backing (`SetBrush(FSlateColorBrush(FLinearColor::White)); SetBrushColor(Hex(TEXT("0F1518")))`) via `Box(Offer, Backing, 1018.f, 246.f, 396.f, 518.f)` (2 px inside the frame rect), then the frame as now with Alpha 1.f. Acceptance: sample (1300,540) within dE 3 of (15,21,24); frame hairline unchanged.

### 4. Disabled "Accepted" label is 1.5:1 against its plate
- **What's wrong:** `SetIsEnabled(false)` dims the whole button, so the dark-ink label (76,61,38) sits on the tint-0.5 plate (103,87,57), contrast 1.54:1. The word is there (section 1) but is the least legible text on screen.
- **Fix type:** CODE (Engineer). Does not block.
- **Instruction:** `SFDialogue.cpp` line 438: keep the button enabled (`HandleAccept` already returns `Stay` when `bAccepted`), and instead apply the section 1 disabled plate: `ApplyButtonStyle(AcceptButton, EButtonKind::Primary, Session.bAccepted ? EHudState::Disabled : EHudState::Normal)` (or the helper's equivalent), leaving the label at `#2A1E10`. Acceptance: label/plate contrast >= 2.5:1; plate tint 0.5 as section 1.
