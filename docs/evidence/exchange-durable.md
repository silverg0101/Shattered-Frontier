# Exchange PostgreSQL durability fixture

On 2026-10-21, `tools/Test-ExchangeDurable.ps1 -EvidenceRoot Artifacts/Persistence/ExchangeDurable/review-fixes-20261021-06` passed with pinned .NET 10.0.402, Npgsql 10.0.3 and PostgreSQL 18.6. The fresh loopback cluster stopped immediately between item delivery and Exchange commit, and separately between a ledger tombstone commit and Exchange commit. Recovery settled or compensated each once. A buyer destination revision advanced after Begin; the receipt still reconciled by operation ID, action and exact item changes. Concurrent buyers produced one sale. Cancelled and expired listings returned escrow once; sold listing cancellation was rejected. Pending and compensated trade cancellation, replay, netted two-way gold offers, payee and listing arithmetic overflow, item-only amount validation, fee sink entries, outages and newer schema refusal passed. `harness.json` reports pass and removal of owned private storage.

The fixture uses separate Exchange and inventory credentials. Exchange has SELECT only on its schema marker, SELECT/INSERT/UPDATE on mutable tables and no DELETE. The inventory fixture credential retains the existing adapter's required DELETE and schema marker UPDATE privileges. `Exchange.Tests`, `InventoryLedger.Tests`, and `MvpJourney.Tests` passed with the pinned SDK. Earlier review-fixes roots `-01` through `-05` exposed privilege or fixture mistakes; all owned private storage was removed. Production authentication, worker fencing, escrow funding orchestration, automatic reconciliation and shared configuration publication remain integration work.

On 2026-10-21, `tools/Test-ExchangeDurable.ps1 -EvidenceRoot Artifacts/Persistence/ExchangeDurable/backup-restore-20261021-02` passed. Shared `Backup-ServiceStore.ps1` and `Restore-ServiceStore.ps1` now accept Exchange schema v3. The v3 database timestamp on pending settlements supports a typed recovery window of 60–86400 seconds, default 3600 seconds, effective per backup or restore invocation. An older schema fails closed. The restore checks wallet balances against entries and sale buyer debit against seller net credit plus fee sink, rejects sold listings with active state, and rejects aged pending settlements. The fixture refused an aged pending source, a flipped-byte dump, and a newer source schema; it restored all table snapshots to the backup point after a later wallet write, then removed the owned restore instance. The recovery window is a tool control for operators; shared configuration publication for runtime Exchange remains open.
