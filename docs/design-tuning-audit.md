# DOC-05 — Bounded tuning-policy audit

Status: reviewed bounded audit, 2026-10-17. Documentation evidence only; no control, default, owner acceptance or runtime behavior is changed.

## Scope and authority

Sample: E1 authoritative movement; H2 terrain geometry/load limits and four construction controls (cache distance, collapse warning, environmental wear, repair cost); REC-03 PITR declaration. This is not an audit of every E1/H2 setting or all 16 construction controls. Authentication, combat/item formulas, economy, other construction controls, all other domains and actual service declaration repositories remain uninspected. Security, LiveOps and other reserved domains remain read-only. No runtime tests were run.

[Tuning policy §§1–3, 7–8][policy] controls editability: an identifier beginning `tune.*` grants no live permission; undeclared controls stay release-bound. Formulas, authorization, security limits, transaction semantics and topology require compatible releases. [Registry §7.1][registry] controls names, registers World/Backend domains and adopts Construction Integration's exact 16 keys. Registry need not repeat every domain-private key: absence from its constants table alone is not a finding.

Defaults below are documented launch/design defaults, not verified shipped software. Numeric operating limits are distinguished from a permitted operator-edit range. “Undeclared” means no complete declaration found in the inspected owning sections, not proof that no implementation exists.

Shared workflow for the four declared construction controls: Construction Integration §9 specifies whole-realm scope, `apply_on = immediate` delivery followed by the listed domain adoption boundary. Persistent publication requires existing LiveOps config privileges; GM capability alone is insufficient. [Config and Releases §2.5][config] requires production gameplay tier 2 (owner lead + `liveops_operator`), economy tier 3 (tier 2 + `economy_analyst`); a numeric change exceeding 25% escalates to tier 3. [Config API §1.2][config-api] supplies `PublishTuning` with `AdminContext`, optimistic version and schema/invariant checks. These references establish the workflow, not a tested permission implementation.

Construction §9 also specifies last-good snapshots, admission blocked without a valid boot snapshot, client-visible effective values/revision, preview, cross-validation, monitoring and prospective rollback. Policy §3's complete declaration requirements still apply (including help, safe fallback, incompatibilities and rollback criteria); this sample does not certify every declaration field or console implementation. Construction §7's delivery gate remains closed pending its implementation evidence.

REC-03 lookup establishes that a complete live declaration was not found in the inspected design authorities. It does not establish a fixed-default compliance defect, an unknown key or absence from every repository. No finding changes DEC-02/03 acceptance, REC-01/02, collision/codec evidence, or measured recovery gates. Owner classification requests remain pending; this audit does not authorize console exposure.
